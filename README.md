# Q-Trade — Angular-каталог MAXHUB

Фронтенд подключён к HTTP API отдельного проекта `Q-trade-business`. Категории, товары, характеристики, блоки страницы и документы загружаются из PostgreSQL через API. Демонстрационные товары и mock API удалены.

## Локальный запуск

Сначала запустите PostgreSQL и бэкенд по инструкции проекта `Q-trade-business`. Проверка: `http://localhost:3000/api/health` должна вернуть `{"status":"ok"}`.

В настройках бэкенда разрешите origins:

```dotenv
FRONTEND_ORIGINS=http://localhost:4200,http://127.0.0.1:4200
```

Затем из корня фронтенда:

```powershell
npm ci
npm start
```

Откройте `http://localhost:4200/catalog`.

В режиме разработки адрес API задаётся в `src/environments/environment.development.ts`; по умолчанию `http://localhost:3000/api`.

## Страницы

- `/` — существующая главная страница со ссылкой на каталог.
- `/catalog` — все опубликованные товары и корневые категории.
- `/catalog/:slug` — категория, её подкатегории и опубликованные товары всей ветки.
- `/products/:slug` — карточка товара, преимущества, варианты, блоки, характеристики и документы.

Поиск, сортировка и номер страницы сохраняются в query-параметрах URL. Переключатель RU/KZ в шапке меняет язык контента, запрашиваемого у API; при отсутствии перевода бэкенд возвращает RU. Перевод всего интерфейса на KZ в этот этап не входит.

Меню строится из реальных категорий. Черновики не показываются: в текущей базе публично доступны только 2 из 42 товаров. Категории без опубликованных товаров показывают пустое состояние.

Цена NULL или `showPrice=false` отображается как «Цена по запросу». Кнопка отправки заявки пока не подключается. Неизвестный остаток не превращается в ноль. Корзина и онлайн-покупка не доступны в интерфейсе каталога.

Хранилище бэкенда пока не настроено, поэтому вместо фотографий показывается заглушка. У документа без URL нет активной ссылки скачивания. Внешняя ссылка производителя отображается отдельно; её доступность бэкендом не проверялась.

## Сборка и SSR

```powershell
npm run build
$env:API_ORIGIN = 'http://localhost:3000'
npm run serve:ssr
```

Собранный сайт доступен по адресу `http://localhost:4000/catalog`; порт можно изменить через `PORT`.

В production-конфигурации браузер обращается к `/api` на origin сайта. Express-сервер фронтенда перенаправляет запросы чтения в бэкенд по `API_ORIGIN`. По умолчанию это `http://localhost:3000`. Для другого окружения задайте origin реального бэкенда в окружении серверного процесса.

SSR читает текущие данные на запрос; статического снимка каталога при сборке нет. Добавленный и опубликованный товар появится при следующем запросе без пересборки Angular. Для обновления меню в уже открытой вкладке перезагрузите страницу. Авторизация и административные API пока не подключены.

## Проверки

```powershell
npm run test:ci
npm run lint
npm run build
```

Проверки каталога находятся в `src/app/features/products/catalog.spec.ts`: иерархия, DTO и язык запросов, пустые изображения/цены, ссылки на карточку, защита расчётов корзины и структурированные данные без выдуманных предложений/рейтингов.

Общий lint также проверяет старые UI-компоненты. На момент подключения каталога в `button.ts`, `input.ts` и `modal.ts` оставались 4 ошибки правил алиасов input и доступности; эти компоненты не изменялись в рамках интеграции.
